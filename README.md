# WRpedia · 英雄联盟手游（Wild Rift）独立数据站

仿 Liquipedia 风格的《英雄联盟手游》赛事数据站，包含概览及以下页面：

- `schedule.html` — 小组赛赛程页：赛制说明、8 队双循环积分榜、全部比赛及每小局 BP 详情
- `stats.html` — 数据统计页：总榜 / 7.2 / 7.3；英雄 BP 梯度、选用/禁用统计、蓝红方胜率、搭档与对手、未上场英雄、比赛时长分布
- `patches.html` — 版本页：7.2c、7.2d、7.2e、7.3 的常规峡谷改动、赛事重点、装备／符文／战场与官方来源
- `picks.html` — 选用查询：队伍 × 英雄 × 版本交叉筛选，展示所有命中小局的完整 BP、位置、红蓝方、胜负、时长与大场信息

内置现有 142 名英雄的英文名、国服中文名、台服原名与昵称、头像（方形图标与官方立绘），均来自官方页面抓取，离线可用。

## 如何打开

直接双击 `index.html` 即可（数据通过 JS 文件加载，不需要本地服务器）。也可以用任意静态服务器：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:8765/`。

## 发布网站

线上地址：<https://wrpedia.netlify.app>。Netlify 站点名为 `wrpedia`，所属团队为 `daransun`；本地 `.netlify/state.json` 已关联该站点，更新时请复用现有站点。

执行 `node tools/build-site.js` 生成 `dist/`，只包含网页、头像和赛事数据。旧截图 `wrl/`、工具和本说明不随网页发布。

项目已提供 `netlify.toml`。完成 Netlify 登录并关联站点后，先重新生成 `dist/`，再运行 `netlify deploy --dir=dist --no-build --prod` 更新线上页面。以后录入比赛或修改昵称后沿用同一站点发布，链接保持不变。

## 录入赛程数据

打开 `data/schedule.js`，文件头部有完整字段说明。核心结构：

```js
window.WR_LEAGUE = {
  meta: { /* 赛事信息；demo: true 时会显示示例提示 */ },
  teams: [
    { id: "ta", name: "队伍A", short: "TA", region: "", logo: "" }
  ],
  rounds: [
    {
      title: "第 1 轮",
      date: "2026-07-04",
      matches: [
        {
          id: "R1M1",
          date: "2026-07-04 17:00",
          timezone: "UTC+8",
          bestOf: 3,
          opponent1: "ta",
          opponent2: "tb",
          mvp: ["选手名"],
          vod: "https://...",
          youtube: "",
          twitch: "",
          games: [
            {
              length: "18:32",
              winner: 2,          // 1 = opponent1 胜，2 = opponent2 胜
              team1: { side: "blue", picks: ["aatrox", "lee-sin", "ahri", "jinx", "lulu"], bans: ["orianna", ...] },
              team2: { side: "red",  picks: ["camille", "wukong", ...], bans: [...] }
            }
          ]
        }
      ]
    }
  ]
};
```

要点：

- `opponent1/opponent2` 引用 `teams` 里的 `id`。id 一旦被赛程引用就不要改，否则要同步修改所有比赛。
- 英雄一律使用小写 slug（见 `data/champions.json`），例如 `khazix`、`lee-sin`、`nunu-and-willump`。也可以在浏览器控制台执行 `Object.keys(WR.champions)` 查看全部 slug。
- 每小局 `picks` / `bans` 各 5 个。未开赛的比赛 `games` 留 `[]` 即可。
- 当前已内置真实 8 队（TT、FP、RV、KBG、WBG、SS1、WHG、ACE）和已校验的双循环赛程（7 周 × 8 场 = 56 场，主客场各一次）。第 1–5 周全部赛果已录入，共 40 个大场、92 小局；第 6 周新增 2 个大场、4 小局，现共 42 个大场、96 小局；其余赛程待录入。
- 队伍全名仅按截图中可见信息填写（Weibo Gaming / Radiant Virtue / SS ONE），其余队伍仍为缩写占位，拿到正式队名后改 `teams[].name` 即可。

## 统计口径（当前实现）

- 总榜保留所有已录入有效小局；7.2 分榜覆盖第 1–5 周，7.3 分榜覆盖第 6 周起。英雄详情、分路、队伍、搭档／对手、蓝红方胜率、时长和未选英雄全部使用同一版本范围。没有比赛样本时显示空状态，不把整个英雄池误标为“未选用”。
- 版本切换可通过 `stats.html?version=7.2` / `stats.html?version=7.3` 分享，支持刷新与浏览器前进／后退。未提供或无法识别的版本参数默认总榜。

- 英雄选用/禁用按**小局**计数：每小局每个选用英雄计 1 次 Pick、每个禁用英雄计 1 次 Ban；胜方英雄计 1 胜、负方计 1 负。
- `%T`（BP 率）分母为该英雄的**有效局数**，受双边无畏征召影响：只要英雄在该大场尚未被任一方选用（未被无畏征召锁定），无论本局是否被禁用/选用，该小局都计入其分母；被选用后，该大场后续小局不再计入。
  - 例：某大场第一局 TT 选用永恩，则永恩在该大场的有效局数为 1，第二、三局不计入。
  - 例：某英雄第一局被 Ban、第二局才被选用，则该大场有效局数为 2（Ban 与 Pick 都计入分子）。
  - 例：某英雄在某大场全程未被选用（即使被禁用或完全未出现），该大场全部小局都计入其有效局数。
  - 英雄被锁定后，后续小局里该英雄的选用/禁用数据也会被忽略（正常赛制下不会出现，属防御性处理）。
- 蓝/红方按该小局 `side` 字段区分；新记录分路按 `pickRoles` 标注，旧记录按 `picks` 数组顺序（上/野/中/下/辅）区分。
- 统计页默认六列：英雄、BP 率、选用次数、禁用次数、选用胜率、有效局数。梯度徽章放在英雄名旁；“详细视图”增加梯度得分、胜负、选用率及蓝红方拆分，所有数值支持排序。点击英雄进入详情。
- 英雄详情弹窗包含：有效局数摘要、梯度得分解释、小版本选用、分路选用与胜率（By Role）、禁用顺位占比（前三 ban / 后两 ban）、使用队伍、搭档与对手。
- 赛程页会对每个大场做**双边无畏征召校验**：若同一英雄在同一个 BO3 的不同小局中被任一方重复选用，会给出警告。禁用在当前实现中按小局独立计算，不做跨局校验。
- 以上逻辑集中在 `assets/js/stats.js` 的 `compute(version)`，浏览器可通过 `WR.computeStats("7.2")` 检查结果。

## 选用查询与分路梯度

- 选用查询由 `assets/js/pick-history.js` 提供纯查询与小局渲染，`assets/js/picks.js` 处理页面交互。中文、英文和昵称共用原有词库；多个英雄匹配时必须选定一个，不把选手昵称误当成单一英雄。未选用显示“该英雄未被此队伍选取”。
- 查询只读取已结束且有选人记录的小局，保留原始局号，胜者编号对应大场的 opponent1/2；页面始终蓝方在前，显示选定队伍的胜负。可直接分享带 team、champion、version 参数的链接，支持刷新和前进／后退。
- 7.2 历史分路依据 picks 的上、野、中、下、辅顺序。新的比赛 picks/bans 按队内实际 BP 顺序保存，由并行的 pickRoles/banRoles 指定实际分路；两个位置以数组记录，各分摊 50%。空 Ban 以 null 保留原顺位，不计入英雄次数。模型为 `assets/js/role-tiers.js`，界面为 `assets/js/role-tiers-ui.js`。通过 `WR.computeStats(version).roleTierModel` 可检查全部分路结果。
- 设 P、W 为本分路选用与胜场，P总 为该英雄全部位置的选用，K 为本路已标注 Ban，U 为英雄未标注分路的 Ban，N 为双边无畏有效局数。分路 Ban = K + U × P / P总（P总 > 0）；分路热度 = (P + 分路 Ban) / (N + 8)；修正胜率 = (W + 4) / (P + 8)；分路强度 = 热度 × 2 × 修正胜率。
- 已标注 Ban 直接计入对应分路（双位置各半），只有未标注部分按当前范围的出场比例估算。所有位置分摊之和等于原始 Ban。缺少选用样本时，未标注 Ban 使用 `data/champion-rules.js` 的站主确认比例：基兰、阿利斯塔为辅助，阿萝拉为中路，塔莉垭为打野，沃里克为上单。已有选用时，未标注部分改按实际比例；无法估算的部分显示分路待确认。某个位置只有 Ban、没有 Pick 时，该路修正胜率中性为 50%，实际胜率显示 —。跨分路选用仍会触发无畏锁定，因此 N 不能只扣除该分路的选用。
- 每个位置用 max(0.25，本位置已评级英雄最高强度) 作比较基准，相对分 = 100 × 强度 / 基准。3 次本位置选用且 12 个有效小局起评级，少于 10 次选用或 30 个有效小局标“初步”。某路只有 Ban 的英雄用分路 Ban 次数代替选用次数判断门槛。其余样本待评级，不强制塞进 T4。
- 分档门槛 OP/T0/T1/T2/T3/T4 为 90/75/55/35/15/0。OP 另需至少 8 次本位置选用、30 个有效小局、修正胜率 ≥ 50% 且强度 ≥ 本位置已评级中位数的 1.5 倍，某路只有 Ban 的英雄的 8 次门槛使用分路 Ban；否则最高 T0。分数先保留一位小数再分档，搜索只过滤展示，不重新排名或计算基准。
- 相对分只能在相同分路和版本内比较；不会按名次人数强行制造断档。该模型是赛事参考，不是英雄绝对强度或经过验证的胜率预测，也未剥离队伍实力、对手和阵容影响。
- 验证：`node tools/check_role_and_picks.js` 覆盖独立手算、分路胜率隔离、Ban 不重复分配、小样本、OP 附加条件、版本隔离，以及全部 142 位英雄 × 8 支队伍查询结果与统计计数核对。

## 英雄 BP 梯度（BP v2）

数据页另有五个位置独立计算的“分路梯度榜”，使用下述分路 v3；此处的总榜 BP v2 继续独立使用原有公式。

这是本站定义的**职业赛事 BP 与胜率综合梯度**，同时考虑选禁热度和实战结果，不等同于英雄绝对强度或胜率预测。参数由站点设定，尚未经过预测效果验证。总榜、7.2、7.3 各自使用当前范围内的数据和平均值重新计算，普通平衡调整不直接加减分。

- P = 选用数，B = 禁用数，W = 选用胜场，N = 双边无畏下的英雄有效局数，沿用原有 BP 分母。
- q = 当前范围 Σ(P+B) / ΣN，b = 当前范围 ΣB / ΣN。包含有可用机会但未被选用／禁用的英雄。
- 加入 8 个当前平均水平的虚拟样本：平滑 BP 率 = `(P+B+8q)/(N+8)`，平滑禁用率 = `(B+8b)/(N+8)`。
- BP 基础分 = `90 × 平滑 BP 率 + 10 × 平滑禁用率`。Ban 已包含在 BP 中，额外 10% 用来体现禁用压力。
- 修正胜率 = `(W+5)/(P+10)`：加入 5 胜 5 负的中性先验，出场越少，越向 50% 收缩。胜率系数 = `2 × 修正胜率`，也等于 `1 + P/(P+10) × (2×原始胜率−1)`（P > 0 时）。
- **综合得分 = `clamp(BP 基础分 × 胜率系数, 0, 100)`**。原始胜率低于 50% 降分、高于 50% 加分、50% 不变。中间值保留精度，最终得分四舍五入到一位小数后分档。
- 所有英雄采用同一规则，不设置英雄名称特例。P = 0、W = 0 时，系数恰为 1，真实战术 Ban 保留 BP 分数；站主已确认基兰的全部 Ban 均为真实战术 Ban，正常计算。
- N < 12 时标为“待评级”；12–29 局标为“初步”。无比赛样本时不生成梯度，也不把英雄归入 T4。
- 固定门槛：OP ≥ 85；T0 ≥ 70；T1 ≥ 50；T2 ≥ 30；T3 ≥ 10；T4 < 10。各档可以为空，不强制按人数比例分配。
- 胜率尚未校正队伍、对手或阵容强弱；平滑只能减弱小样本影响，不能消除这些混杂因素。历史选人数组按分路排列；新记录保留队内选取顺序，并以独立位置标注计算分路。
- 梯度总览展示分数和原始胜率；点击英雄查看战绩、修正胜率、BP 基础分和胜率加减分。详细视图的梯度得分列可按综合得分排序。T4 包含已达到样本要求但没有 BP 记录的英雄，默认折叠；检索时自动展开匹配项。
- 模型在 `assets/js/bp-tiers.js`；入口为 `WR.BPTiers.evaluate(stats)`。`computeStats` 为每位英雄附加 `tier`，并返回 `tierModel` 保存该范围的基准。
- 如将来确有非战术 Ban（如赛事统一限制），可在 `meta.bpTierExclusions` 中按 slug 填写排除原因。这只排除梯度及其平均值计算，不改写原始 BP 记录；当前未排除任何英雄。异常计数（含胜负之和不等于出场数）也不参与评级。
